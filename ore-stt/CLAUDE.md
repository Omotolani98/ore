## What this service is

`ore-stt` is the speech-to-text daemon for the Ore agent system. Single responsibility: **audio bytes → transcript**. It is the only Python service in an otherwise Go stack; the boundary is gRPC. It has no knowledge of the agent, LLM, or tools.

Out of scope by design: VAD beyond optional silence trimming, wake-word, diarization, translation/language detection (English only), TTS, audio analysis, format conversion beyond WAV + PCM_S16LE.

```bash
uv sync                       # install from uv.lock

make lint                     # uv run ruff check src tests
make format                   # uv run ruff format src tests
make typecheck                # uv run mypy src   (strict mode)
make test                     # uv run pytest -m "not e2e" tests/   (fast: unit + integration)
make test-e2e                 # uv run pytest tests/   (loads real model — manual/GPU runner only)
```

Run a single test: `uv run pytest tests/unit/test_decode.py::test_name`. `uv run` activates the venv implicitly — no `source .venv/bin/activate`.

## Hard constraints

- **Python 3.11 only** (`>=3.11,<3.12`). `nemo-toolkit` breaks on 3.12+. Do not loosen the pin.
- **`uv`** for deps, **`ruff`** for lint+format, **`mypy --strict`** for types. No poetry, black, isort, flake8.
- **`numpy<2.0`** pinned.
- `src/`-layout: all code under `src/ore_stt/`. No flat layout.
- Generated gRPC code lives in `src/ore_stt/grpc/generated/` and is **gitignored** — regenerated by `make proto` / CI / Docker build. `mypy.ini` and `.ruff.toml` exclude it from checks.
- The `.proto` at repo root `proto/ore/stt/v1/stt.proto` is the API source of truth, shared with the Go agent. Edit it before regenerating stubs.

## Architecture (big picture)

Single process, single resident model. `server.py` starts the gRPC server and the FastAPI admin app together in one process — no multi-worker, because one resident Parakeet dominates memory and NeMo's `transcribe()` is not concurrency-safe.

Request flow (`grpc/service.py` → `audio/` → `asr/`):

```
bytes -> decode (WAV via soundfile / PCM via numpy.frombuffer)
      -> downmix to mono -> resample to 16kHz (only if needed)
      -> optional silero-vad trim -> ParakeetModel.transcribe()
      -> TranscribeResponse
```

Canonical internal audio form: `numpy.float32`, mono, 16 kHz, `[-1.0, 1.0]`.

**Model layer** (`asr/model.py`): `ParakeetModel` wraps NeMo so nothing else imports NeMo directly. Loaded eagerly in a background task at startup (lazy load = 5–8 s first-request spike). `warmup()` runs one no-op inference after load. A single `asyncio.Lock` serializes `transcribe()`; waits over `STT_QUEUE_WAIT_TIMEOUT_MS` fail with `RESOURCE_EXHAUSTED`.

**Admin HTTP** (`http/admin.py`): FastAPI on `STT_ADMIN_PORT` (8080). `/healthz` = process up (never depends on model). `/readyz` = 503 until model loaded. `/info` = ops metadata. No POST, no mutations.

**Config** (`config.py`): env vars only, via a `pydantic-settings` `Settings` class. Everything reads `Settings()`, never `os.environ` directly. All vars prefixed `STT_` (see §8 of ARCHITECTURE.md).

**gRPC error model**: errors are gRPC status codes, not in-band fields. Server validates in fixed short-circuit order (format → non-empty audio → sample_rate set → duration ≤ max → mono). See §4.2/§4.3 for the full code mapping. Streaming RPC `TranscribeStream` is defined in the proto but must return `UNIMPLEMENTED` in v1.

**Logging** (`log.py`): `structlog`, JSON lines to stdout. Every line carries `request_id` (when in request context) and `service: "ore-stt"`.

## Testing layers

- `tests/unit/` — pure functions (decode, resample, VAD bounds, config, error mapping). No model. Runs every commit.
- `tests/integration/` — gRPC handler over an in-memory channel with a **stub `ParakeetModel`** returning canned results. Tests wiring, not the model.
- `@pytest.mark.e2e` — loads the real model, asserts WER on fixture WAVs. Manual / nightly GPU runner only, never on every commit.

## Code style

- **Type hints everywhere.** mypy strict catches missing ones; don't disable.
- **Frozen dataclasses for value types.** Mutable state lives in classes with explicit methods.
- **Async-first.** The server is asyncio-based. Don't introduce thread-based concurrency without strong reason.
- **No top-level side effects.** No `print`, no I/O at import time. Everything starts in `server.main()`.

## Things to never do

- Never import NeMo outside `src/ore_stt/asr/`. The model layer is the only place that touches it.
- Never write audio to disk. Raw audio is held in memory and discarded after transcription.
- Never edit `src/ore_stt/grpc/generated/` by hand. Regenerate with `make proto`.
- Never add a second resident model. One process, one model. Concurrency is via `asyncio.Lock`.
- Never lazy-load the model on first request. Eager load + warmup at startup is intentional.

## When adding a new gRPC method

1. Edit `proto/ore/stt/v1/stt.proto` (this affects `ore-agent` too — flag in PR description).
2. `make proto` to regenerate stubs.
3. Implement the handler in `src/ore_stt/grpc/service.py`.
4. Add integration tests in `tests/integration/test_grpc.py`.
5. Update `ARCHITECTURE.md` §4 (gRPC contract).
6. Update `../ore-agent/` client to consume the new method **in the same PR**.

## When adding a new config option

1. Add the field to `Settings` in `src/ore_stt/config.py` with a default.
2. Document it in `ARCHITECTURE.md` §8 (Configuration).
3. If it has runtime impact, log the resolved value at startup so it's visible in logs.

## Common subtle bugs to watch for

- **Sample rate mismatch.** Parakeet expects 16 kHz. Anything else must be resampled before inference. Validation should happen in `audio/decode.py`, not deep inside `asr/model.py`.
- **Stereo input.** Downmix to mono with a logged warning. Don't reject; the Swift app may send stereo by default.
- **Lock starvation.** The model lock has a wait timeout. If you add new code paths that acquire the lock, respect the timeout — don't introduce indefinite waits.
- **gRPC message size.** Default is 4 MB; we bump to 16 MB for 2-minute WAVs. Don't lower this without checking caller assumptions.
